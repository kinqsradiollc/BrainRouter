# 0.4.17 — Unreleased

0.4.17 is the active product-completion release. These notes accrue as each
independently reviewed slice reaches the release branch; an item listed here is
still unreleased until the final build, security, version, and publish gates pass.

## Added

- **Typed workspace setup.** Projects can store a safe, committable
  `.brainrouter/workspace.json` describing their profile, domain agent,
  capabilities, skills, tool profiles, memory posture, and instruction file.
- **Recoverable project commits.** Approved instruction changes and the workspace
  manifest are treated as one logical commit with bounded crash recovery,
  concurrency checks, symlink protection, and exact rollback.
- **Recoverable global setup.** Provider/model/MCP configuration and the global
  completion marker now commit as one recoverable transition instead of two
  unrelated writes.
- **Explicit workspace setup re-entry.** The CLI can reopen project setup in edit
  mode while preserving safe unknown manifest fields for forward compatibility.

## Changed

- **One engineering identity.** Frontend work is an engineering capability that
  activates for relevant tasks; it is not a separate persona or default agent.
- **Ordered onboarding.** Successful first-run global setup may continue into the
  current project setup, while a later workspace runs only project setup. Skip or
  cancellation never undoes already committed global configuration.
- **Commit-first live configuration.** Model, MCP, login, logout, and desktop
  account transitions persist successfully before mutating live runtime state or
  reporting success.
- **Connection-confirmed brain selection.** A requested BrainRouter server becomes
  the live selection only after connecting. Failed switches preserve the prior
  usable brain and later reconnect target.
- **Credential-safe endpoint editing.** Legacy inline credentials are redacted or
  removed during editing and logout instead of being rendered back into prompts,
  status output, or runtime projections.

## Fixed

- **Partial setup recovery.** Process interruption between paired file writes no
  longer leaves an owned partial update without a deterministic recovery path.
- **Desktop account consistency.** Sign-in uses the selected brain even when it is
  not first in the catalog, and sign-out cannot reconnect a profile whose durable
  credentials were removed.
- **Concurrent-writer safety.** Setup rollback preserves a replacement created by
  another process rather than overwriting work it cannot prove it owns.

## Tests / Verification

- Full detached `npm run verify` passes with the same PostgreSQL environment used
  by CI, including 192 integration, 970 CLI, and 354 desktop tests.
- Full root `npm run build` passes, including optimized dashboard and desktop
  production builds.
- Focused crash-recovery, credential-removal, failed-switch, reconnect, and
  desktop account-lifecycle regression suites pass.
