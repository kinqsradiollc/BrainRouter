# 0.4.8 — Deterministic multi-phase workflow orchestration

0.4.7 made the agent *reason* about whether to fan out; 0.4.8 gives that reasoning
a **runtime to execute**. The headline is a native, deterministic multi-phase
workflow engine: the system hands over a declarative plan **once** and the runtime
drives every step — fan out N specialist children per phase, **barrier-wait the
whole phase**, synthesize their outputs, and feed that forward into the next phase
— durably persisted and **crash-resumable**. It's the phased fan-out-then-synthesize
pattern (reviewers per target → a synthesizer) as a first-class capability instead
of something the model has to hand-orchestrate turn by turn. Plus a brain-server
fix for oversized request bodies.

Every item shipped as its own branch → PR → green CI → merge into `release/0.4.8`
(PRs #253–#263, 11 total). Full suite green: **522 brain unit + 150 integration +
1194 CLI**.

## Workflow orchestration (the headline)

- **`PhasePlan` + deterministic executor (WF-PLAN #254, WF-ENGINE #255).** A
  declarative plan — ordered phases, each either an explicit `agents` list or a
  `fanOut` over targets, with `inputFrom` / `dependsOn` / `synthesize` — is executed
  by a runtime engine that spawns each phase's children through the existing spawn
  chokepoint, **barrier-waits the entire phase**, synthesizes, and injects that
  synthesis as `{{input}}` into downstream phases. The model doesn't drive the
  spawns; the runtime does.
- **Durable, crash-resumable runs (WF-PERSIST #256, WF-RESUME #263).** Each run is a
  phase-aware ledger (`childIds`, per-phase output, status) that survives a CLI
  restart; a crash flips the in-flight phase to `interrupted`, and a run can be
  **resumed from its failed phase** — completed phases are skipped and their saved
  output feeds the rest.
- **`run_workflow` tool (WF-TOOL #257).** One tool call hands over a `PhasePlan` (or
  a template); the runtime fans the wave out via `spawn_agents`/`wait_agents` in
  `cli.maxConcurrentChildren`-sized batches, synthesizes, and persists — no manual
  spawn/wait/synthesize.
- **The system runs it for you (WF-PLANNER #259).** When the next-action planner
  picks the `workflow` strategy it now emits a **validated `PhasePlan`** and the
  agent's first action is a single `run_workflow` call — the agent fans out *by
  itself* instead of single-threading.
- **Built-in templates (WF-TEMPLATES #258).** `compare` (analyze each option →
  recommend), `review-wide` (review each target → merge findings → summarize), and
  `research` (research each angle → synthesize) — one call, no hand-authored plan.
- **Real findings merge (WF-SYNTH #260).** A `review-merge` phase now dedupes +
  confidence-thresholds structured findings across reviewers (not just a role
  rollup), falling back gracefully when none are present.
- **`/workflows` is a launcher + live phase timeline (WF-LAUNCH #261).** `/workflow
  run <template> [args]` kicks off a run; the viewer renders the phase glyph strip +
  per-phase agent counts / durations.
- **Background runs (WF-BG #262).** `run_workflow({ background: true })` runs detached
  so a long fan-out doesn't block the REPL; the background panel shows live
  `phase N/M` progress.

## Brain server

- **No more `PayloadTooLargeError` (BRAIN-BODY-LIMIT #253).** The HTTP server mounted
  `express.json()` with body-parser's stock **100 kB** limit and no error handler, so
  a large MCP/capture payload threw an unhandled error (raw 500/crash). The limit is
  now configurable (default **16 MB**, `BRAINROUTER_MAX_BODY_SIZE`) and an oversized
  body returns a clean **413** instead of taking the process down.
