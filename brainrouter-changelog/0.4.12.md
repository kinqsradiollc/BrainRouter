# 0.4.12 — The Build Loop, and multi-agent runs that don't quit early

0.4.12 composes the 0.4.11 worktree-isolation substrate, roles, and the phase
engine into one opt-in **plan → implement → verify → review → merge** loop, and
hardens the whole multi-agent surface so long runs **reconnect instead of timing
out**, children **merge or hold for review** instead of stranding work, and the
parent loop **keeps going** when a child outruns its drain window. Single-agent
chat stays the default; everything here is opt-in or a pure reliability fix.

## The Build Loop

- **`/build <task>`** runs an explicit engineering loop —
  **plan → implement → verify → review → merge** — over the existing role and
  phase machinery. Implement, Verify, and Review attach to **one phase-scoped
  shared worktree**, so the verifier runs against the worker's actual edits, and
  a **merge gate** lands the changes only when Verify is green and Review raises
  no blocker. A red or blocked run keeps its work as a recoverable patch
  (`/agents diff <id>`) instead of touching your tree.
- **Escalation — `cli.buildLoop`** (`off` · `escalate` · `always`, default
  **`escalate`**). On `escalate`, the next-action planner classifies a
  multi-file / multi-step request and fires a single build run on your behalf;
  `off` downgrades a stray build pick back to a normal investigation; `always`
  routes qualifying work through the loop.
- **Fan-out builds.** A build with more than one slice fans out **one held
  worktree per slice**, then a **synthesis-review** phase reads the combined set.
  `finalizeFanOutBuild` runs cross-worktree structural-overlap detection and an
  overlap-aware, gated, sequential merge (first-writer-wins; a blocker holds the
  whole set). Every held slice is recoverable via `/agents diff`.
- **`cli.worktreeMergeReview`** (`off` · `on`, default **`off`**). When `on`, an
  ad-hoc isolated write child **holds** its clean changes as a reviewable patch
  instead of auto-merging — the same hold-for-review gate the build loop uses,
  extended to `/spawn` workers.
- **Loop-until-green self-repair — `cli.buildLoopMaxRepairs`** (number, default
  **`0` = disabled**). When greater than zero, a single-worktree build whose
  Verify comes back red re-runs Implement → Verify → Review in the **same**
  worktree — feeding the failure back to the worker — up to N times, stopping at
  the first green, else preserving the patch. Opt-in by design.
- **Active phase, surfaced.** `/ps`, `/agents`, and the statusline now show the
  running phase and position (e.g. `slug · Implement (2/4)`), sourced from the
  run ledger. A new opt-in `phase` statusline segment (`▶ Implement (2/4)`) shows
  it during `/build`; the default statusline is unchanged.

## Multi-agent runs that keep going

- **The parent loop auto-resumes (C1).** When a turn ends with child agents that
  outran the drain window, the REPL **polls** them and, once they all settle,
  fires a synthetic continue (drain + synthesize) — the automatic equivalent of
  `/continue`. Always on, **cancelled by your next keystroke**, and bounded (it
  gives up after ten minutes; a manual `/continue` still works).
- **Type while it's busy (C2).** A prompt entered mid-turn is now **queued**
  instead of dropped, then drained one at a time after each turn settles. `/queue`
  lists the pending messages, `/queue remove <n>` drops one, `/queue clear`
  empties it. Slash commands still dispatch immediately.
- **Reconnect instead of time out.** Model calls and the memory / MCP transport
  now **reconnect with exponential backoff** (honoring a server `Retry-After`,
  connectivity-aware, with a visible "Reconnecting n/max") rather than failing at
  a hard wall-clock deadline. A genuine memory-recall timeout still fails fast —
  only true connection drops reconnect — so briefing stays responsive.
- **Timeouts wait, they don't kill.** Child-agent **and** worker-thread timeouts
  now bound only how long the **parent waits** — they never terminate the child
  or worker. An elapsed wait returns a status envelope while the work runs to
  completion; `timeoutMs: 0` (the default) waits until done across the spawn /
  wait / worker tools. Inner loops stay bounded by `maxToolLoops`, the per-call
  timeouts, and reconnect, so nothing hangs forever.
- **Live worktrees are safe from the GC.** The orphan-worktree reconciler no
  longer removes a **running** child's worktree out from under it — the cause of
  spurious `ENOENT` failures on every subsequent tool call.

## Accuracy fixes

- **Filesystem search actually searches.** The `grep_search` tool now does real
  **regular-expression** matching (with a literal fallback for invalid patterns)
  and accepts a directory **or** a single file; before, regex queries silently
  matched nothing. Build / cache directories (`.next`, `.open-next`, `.turbo`,
  `coverage`, `.claude`, `.brainrouter`, …) are ignored during traversal.
- **Workflow roles degrade gracefully.** An unknown agent role no longer throws —
  it maps by intent (audit / security / review → reviewer, qa / test → verifier,
  plan / design → architect, implement / build → worker, else explorer) so a
  workflow with a custom role name still runs.
- **`/tokens` counts the whole tree.** The session cost now folds in
  child / sub-agent tokens, labelled `(parent + children)` with an
  `incl. ~$X from N child agents` breakdown — no more undercounting delegated work.
- **Worker state moved home.** Persistent worker-thread state now lives under the
  BrainRouter home CLI state directory instead of the per-workspace
  `.brainrouter/`, so it survives workspace-local resets and matches the
  federation registry layout.
