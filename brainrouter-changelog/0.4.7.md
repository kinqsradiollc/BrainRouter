# 0.4.7 — Coding-agent parity, agentic autonomy, and staleness-aware memory

0.4.6 reshaped the codebase into concern-scoped modules; 0.4.7 builds the **Codex
coding-agent parity track** on those seams. Three themes: close the execution-safety
gaps that separated BrainRouter from a hardened coding agent (sandbox, command
approval, MCP egress, worktree isolation, atomic patches), make the agent *actually*
fan out and follow through instead of promising work and stalling, and teach recall
to flag a memory whose underlying source code has since changed.

Every item shipped as its own branch → PR → green CI → merge into `release/0.4.7`
(PRs #236–#251, 16 total). Full suite green: **512 brain unit + 150 integration +
1120 CLI**.

## Coding-agent parity — execution safety

- **Fail closed when the sandbox is requested but unavailable (CODEX-SANDBOX-FAILCLOSED, #237)** —
  a shell tool that asked to run sandboxed used to fall through to an *unsandboxed*
  run on a host with no sandbox. It now refuses (exit 126, `refused`), with a
  platform-aware decision (`decideUnavailableSandbox`) and stderr-denial detection,
  so "sandboxed" never silently means "not".
- **Command-segment approval precision (CODEX-EXEC-POLICY, #239)** — `run_command`
  approval is evaluated per shell segment (pipes / `&&` / `;`), classifying each as
  dangerous / allowlisted / safe / unknown instead of judging the whole string by its
  first token. A new opt-in `cli.commandAllowlist` lets a workspace pre-approve exact
  command prefixes.
- **Over-broad allowlist prefixes rejected (CODEX-APPROVAL-GUARD, #241)** — an
  allowlist entry like `git` or `npm` (which would wave through `git push` /
  `npm publish`) is now rejected at config load; `sanitizeCommandAllowlist` drops the
  over-broad prefix with a warning so a careless knob can't open a hole.
- **Atomic `apply_patch` (CODEX-APPLY-PATCH-HARDEN, #240)** — patches now prevalidate
  *every* operation (parse the envelope, assess safety, locate context) before a
  single byte is written, then flush. A patch that would half-apply and leave the
  tree in a torn state is rejected whole instead.
- **MCP network/egress gated; readOnly-hint bypass closed (CODEX-MCP-APPROVAL, #247)** —
  destructive- and egress-named MCP tools (broadcast / sync / transfer / webhook /
  upload / http / fetch …) are now checked **before** a server-supplied
  `readOnlyHint` can wave them through, so a tool can't self-declare its way past
  approval.
- **Per-child git worktree isolation + cleanup, safe by default (CODEX-WORKTREE-CLEANUP, #246)** —
  a child agent's worktree is now reliably removed when it finishes (diff captured
  first), orphaned worktrees are reconciled on REPL boot, and the
  `cli.childWorkspaceIsolation` default flips from `auto` to **`off`** — isolation is
  now opt-in rather than a surprise.
- **`/review` can't collapse or stall (REVIEW-FIX, #236 / #238)** — a read-mode parent
  can correctly fan out a read-access child (the policy used to forbid it), and
  `/review` runs through one authoritative diff-injected prompt instead of a
  second five-axis path that could stall or double-review.

## Agent lifecycle & orchestration

- **One tool registry (CODEX-TOOL-REGISTRY, #242)** — every local tool now has one
  registry entry (access tier, action kind, parallel-safety); the model-visible tool
  list, the exec policy, and the parallel-safe set are all *generated* from it, and a
  guard test fails if registry, policy, parallel set, and specs ever drift apart.
- **Spawn slots — cap a parent's concurrent children (CODEX-AGENT-LIFECYCLE, #243)** —
  a parent agent now has a bounded number of in-flight children
  (`cli.maxConcurrentChildren`, default 8); excess spawns wait for a slot instead of
  fork-bombing, counted on *running* children and scoped per parent session.

## Agentic autonomy — the agent acts instead of stalling

- **Next-action planner (NEXT-ACTION, #250)** — the headline of the release. Instead
  of keyword-matching the prompt to guess whether to fan out, the runtime now runs a
  short **reasoning step** at turn start that picks a strategy —
  `answer-direct` / `investigate` / `fan-out` / `workflow` — and injects a decisive
  directive. The system *reasons about what to do next* rather than pattern-matching
  hints. Gated by `cli.nextActionPlanner` (default `on`); the prior breadth-hint path
  remains as a fallback.
- **Fan-out fires on analytical comparisons, and follows through (#248 / #249)** — a
  multi-target comparison ("compare A vs B, C, D") now triggers fan-out (the breadth
  detector missed it before), and a new follow-through guard catches the case where
  the hint fired but the agent *didn't* actually spawn — nudging it to spawn rather
  than answer from a single thread.
- **Parallel tool calls show they're running (#244)** — when several tools run at
  once the UI now renders `N tools running in parallel: …` instead of looking hung,
  so concurrent work is visible.
- **No more "promise then stall / promise then ask" (#244 / #245)** — the turn-end
  guards catch the pattern where the agent announces imminent tool work ("let me
  check…") and then *ends the turn* or asks a question instead of acting. Bounded
  guards (`promisedToolsAtCount`, fan-out follow-through, capped so they can't loop)
  push the agent to follow through on what it just said it would do.

## Memory accuracy

- **Code-staleness-aware recall (MEM-ACCURACY, #251)** — a recalled memory derived
  from code whose source file has since changed is now **flagged and down-ranked**.
  The recall pipeline checks each code-anchored record against its source-chunk
  provenance (`isRecordSourceStale`), sinks stale records among the selected hits, and
  annotates the briefing line with `⚠ source changed since capture — verify against
  current code` — so the agent re-verifies against the live code instead of trusting a
  memory the codebase has outgrown.
