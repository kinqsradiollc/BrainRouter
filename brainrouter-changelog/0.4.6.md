# 0.4.6 — Structural refactor (modular, concern-scoped layout)

0.4.5 finished the product surface; 0.4.6 reshapes the codebase under it. This is a
**behavior-preserving** release: the load-bearing monoliths — the CLI agent, the
memory engine, the Ink chat UI, and the dashboard page — are decomposed into small,
concern-scoped modules so the codebase is easier to reason about, test, and extend.
**No user-facing changes.** The public `Agent` API, the `IMemoryStore` facade, and
the MCP tool surface are identical; this is internal structure only.

Every item shipped as its own branch → PR → green CI → `--no-ff` merge into
`release/0.4.6` (PRs #222–#234, 14 total). Full suite green: **508 brain unit +
150 integration + 1049 CLI**.

## Changed (internal — no behavior change)

### Engine & MCP server (`brainrouter`)

- **Exec concerns consolidated under `runtime/exec/` (REFAC-EXEC-MODULE, #222)** —
  the exec-policy, sandbox, and command/approval bits are grouped into one
  concern-scoped namespace with a barrel re-export, so every caller keeps working
  while the exec surface becomes one place to read.
- **Engine domain logic extracted (REFAC-ENGINE-SPLIT, #228/#229/#230)** — the
  logic-heavy lesson, blackboard, and tree operations move out of `memory/engine.ts`
  into `lessons/lessonOps.ts`, `blackboard/blackboardOps.ts`, and `tree/treeOps.ts`
  as free functions taking the engine instance; `MemoryEngine` stays the facade and
  delegates. (`engine.ts` 2011 → 1822 LOC.) The thin one-line store pass-throughs
  (users / memory-CRUD / evidence) intentionally stay on the facade — extracting
  them would be indirection without value.

### CLI (`brainrouter-cli`)

- **Apply-patch extracted to `agent/applyPatch/` (REFAC-APPLY-PATCH-MODULE, #223)** —
  the patch-envelope handler and parser move out of the ~4.6k-LOC `agent/agent.ts`
  into their own module, alongside a new `workspaceFs.ts` for the filesystem helpers.
- **Tool specs/names extracted to `agent/tools/` (REFAC-TOOLS-MODULE, #224)** — the
  local tool specs and name constants move into a `tools/` namespace, carving the
  seam the tool registry sits behind.
- **Orchestration tool factories extracted (REFAC-AGENT-ORCH, #226)** — the ten
  stateless tool-spec factories move to `orchestration/agentTools.ts`. The spawn
  control-plane (`handleSpawn` + dispatch) is intentionally kept cohesive in
  `tools.ts` — it shares mutable state and self-calls, so splitting it would leak
  internals for no gain.
- **`ChatApp.tsx` decomposed (REFAC-CHATAPP-SPLIT, #225/#227/#231/#233)** — the
  reasoning/effort helpers (`reasoningWindow.ts`), the slash-command palette
  (`SlashPalettePanel.tsx`), the footer (`FooterStatus.tsx`), and the scrollback row
  (`ScrollbackRow.tsx`) move into submodules; the mounted tree and behavior are
  identical. (`ChatApp.tsx` 1612 → ~1050 LOC.)

### Dashboard (`brainrouter-dashboard`)

- **Landing data + demo state machines extracted (REFAC-DASHBOARD, #232/#234)** — the
  landing animation variants, demo data, and graph types move to
  `components/home/landingData.ts`, and the two interactive demos' state machines
  move into `useConsolidationDemo` / `useSnnSimulator` hooks; the rendered pages and
  routes are byte-identical. (`app/page.tsx` 1752 → 1636 LOC.)

## Kept whole by design

Two big stateful classes were **deliberately not force-split**, because doing so
would expose private internals and *hurt* maintainability:

- **`memory/store/sqlite.ts`** is the data-access layer behind `IMemoryStore` (176
  inline prepared statements + 26 cached handles); it's already at the right
  boundary. If it's ever split, it should become real per-domain store classes each
  owning their own handle — a deliberate architecture change, not a mechanical move.
- **The `Agent` class / `runTurn` core** stays cohesive behind its public API; the
  standalone helpers around it were the parts worth extracting, and they're out.

## Deferred

- **Deeper dashboard decomposition** — the data and per-demo hooks are extracted; the
  remaining large JSX render tree is risky to split without a unit-test net for low
  gain, so it waits.
- **Shared-package promotion** — promoting framework-free concerns into `packages/*`
  is deferred until concrete cross-package duplication is identified.
- **Test colocation** — colocating `*.test.ts` next to source (vs the central
  `src/tests/`) is optional and low-value; deferred.
