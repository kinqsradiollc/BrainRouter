# 0.4.15 — The requirement-first workflow

> **In progress on `release/0.4.15`** — not yet tagged or published. This file
> tracks the workflow scope as it lands; the full roadmap (agent-behaviour
> subsystems + Desktop) lives in [`../brainrouter-roadmap/0.4.15.md`](../brainrouter-roadmap/0.4.15.md).

0.4.15 turns BrainRouter into a requirement-first coding workflow that stays
durable and memory-backed end to end:

`requirement clarification → structured requirement → linked plan → durable
session-scoped tasks → coding → review & annotation → verification → memory`

BrainRouter memory remains the source of truth: requirements, clarifying
answers, plan links, review findings, and annotation decisions all capture into
the existing memory pipeline (no parallel store), each record carrying full
provenance — workspace, session key, requirement/task/artifact ids, linked
memory ids, and timestamps.

## Requirement records & clarification

- **Requirement records.** A durable, per-workspace requirement: id, title,
  description, status (`draft · clarifying · ready · in-progress · done ·
  archived`), priority, acceptance criteria, clarifying Q&A, and links to
  session / tasks / artifacts / review findings / memory. Shared
  `RequirementRecord` contract in `packages/types`; durable store + `/requirement
  create · list · show · update` in the CLI.
- **Clarification flow.** `/requirement ask · answer · clarify` turns an
  ambiguous request into a structured requirement — record clarifying questions,
  answer them, and get a next-step hint when it's ready. `ask`/`answer` capture
  the decision into memory.
- **Plan seeding.** `/requirement seed-plan` generates one plan item per
  acceptance criterion, anchored to the requirement.

## Durable plans, tasks & modes (session-scoped)

- **Plans linked to requirements.** A plan carries its `requirementId`, carried
  forward across `update_plan` edits, so plans/tasks are scoped by workspace +
  session key + requirement id. (Per-session plan persistence + restore-on-resume
  was already in place.)
- **Session-scoped modes.** Execution mode, review policy, and effort are now
  per-session (not workspace-shared): each chat keeps and restores its own
  stance. The `run_command` gate, system prompt, status line, `/where`, and the
  `/mode · /review-policy · /yolo · /effort` toggles all read the resolved
  session mode; spawned children snapshot the mode at launch.

## First-party annotation & review

- **Annotation system.** BrainRouter's own annotation/feedback records — no
  external product. An annotation can target a plan, requirement, markdown/HTML
  artifact, code diff/file, agent message, or review finding, with an optional
  anchor (file/line/block/text), a suggested replacement, a status lifecycle
  (`open · accepted · rejected · resolved · ignored`), and links to
  session/requirement/task/artifact/memory. Shared `AnnotationRecord` contract +
  CLI store + `/annotation add · list · show · status · export`. **Export**
  emits agent-readable markdown back into the active session and captures it to
  memory.
- **Review triage.** Review findings gained non-blocking triage statuses
  (acknowledged / disputed / out-of-scope) on top of the existing review engine
  and commit gate.

## Desktop workflow surfaces

- **Requirements panel** — browse/create/update requirements, manage status &
  priority, add acceptance criteria, and seed a plan.
- **Annotations panel** — filter by status/target, review the full record
  (anchor · suggested code · provenance links), change status, and export
  feedback into the chat. The Review panel can turn a finding into a durable
  annotation in one click.
- **Live git state** — the environment card re-reads the branch on window focus,
  so a branch switched in another terminal no longer shows stale.

## Foundations

- **`App.tsx` modularized** — the desktop shell dropped from ~2065 to under 900
  lines, decomposed into focused hooks and components (the renderer now
  coordinates layout/state wiring only), matching the layered architecture
  rules.
