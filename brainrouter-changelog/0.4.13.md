# 0.4.13 — Sub-agent results that come back

0.4.13 closes the gap where a spawned sub-agent (or workflow) would finish but the
main agent never delivered its result — you'd watch the child complete, then get
silence. Completed children now flow back to the main agent as a synthesis
continuation — by poll **and** by completion event — with a guard for models that
defer instead of answering, and direct id-correlation when you ask "is it done?".

## Sub-agent results that come back

- **Completed background agents resume the turn.** When a turn ends with spawned
  children still finishing, the REPL now arms an auto-resume for **any** child it
  never synthesized — not only ones that hit the drain timeout. Once they settle, it
  delivers their results without a manual `/continue`.
- **Completion is an event, not just a notice.** A child finishing while the REPL is
  idle now triggers the synthesis immediately (it previously only printed a
  "✓ completed" line). The status poll remains as a fallback; your next keystroke
  cancels either.
- **No more "I'll summarize later".** If a sub-agent returned its findings inline but
  the model ends the turn with a deferral instead of using them, a bounded guardrail
  forces one synthesis pass so you get the actual answer.
- **"Is it done?" resolves the right agent.** When you ask about a running child, the
  agent now checks the exact pending id(s) directly instead of guessing one out of a
  long agent list.

## Also in 0.4.13

- **Parallel tool results pair to the right header.** Two same-name tool calls running
  at once (e.g. two file reads) no longer render both results under the last call's
  header — each result now pairs with its own call.
- **Cleaner citations.** A `file:line` citation garble that some smaller models emit
  is repaired automatically in the answer.
- **Faster first step.** The pre-turn next-action planner now runs at low effort —
  it's a quick strategy classification, not deep reasoning — cutting dead time before
  a turn begins on slower models. It stays fully skippable via `cli.nextActionPlanner`.
