# 0.4.18 — 2026-08-01

0.4.18 is a Desktop quality release. It gives the
workbench a platform-adaptive visual system, more native window behavior, and
faster state-preserving panels while keeping agent, browser, and terminal
authority unchanged.

## Added

- **System-aware appearance.** Desktop now resolves System, Light, Dark, and
  High Contrast modes through the native host and applies the matching canvas
  from startup.
- **Unified native workbench styling.** The window shell, navigation, Chat,
  composer, Settings, Editor, Files, Terminal, Browser, Track, Atlas,
  workflows, meetings, and review surfaces now share one semantic visual
  language with platform-appropriate controls.
- **Visible phase execution.** Plans can carry ordered phases and steps that
  advance across CLI and Desktop, so users can see the active phase, completed
  work, and what remains.
- **Steering-aware plans.** Mid-turn steering is reconciled with the current
  plan at a safe boundary, with the resulting plan revision reflected in the
  task view instead of silently changing direction.
- **Workflow-skill preflight.** Before protected work begins, the agent loads
  the required workflow guidance and reports the preflight state instead of
  entering a repeated tool-failure loop.

## Changed

- **Faster large workspaces.** Files uses a virtualized flat projection for
  large trees, keeps expansion state across Files and Editor, and renders only
  the rows visible in the current viewport.
- **Lighter Editor startup.** The code editor remains a separate lazy-loaded
  chunk and now sits beside an integrated file browser with consistent native
  tabs and control states.
- **Persistent panels.** Inactive right-panel views remain mounted, preserving
  local state and avoiding expensive teardown and reconstruction while moving
  around the workbench.
- **Clearer Queue and Steer states.** The composer shows running, queued, and
  steer-pending states using the same interaction language as the plan view.
- **Safer repository ownership.** Agents preserve, layer on, or isolate
  unrelated work. Checkout, restore, reset, clean, stash, and revert are no
  longer offered as generic recovery steps.
- **Modular visual ownership.** Foundation, shell, and surface styles are split
  into ordered modules so changes can remain small and reviewable.

## Fixed

- **Panel event accumulation.** Reopening panels no longer adds an unbounded
  number of native agent-event listeners.
- **Browser interaction latency.** Native tab creation, switching, and bridge
  dispatch have bounded release gates, while background agent tabs remain
  isolated from the user's active tab.
- **Packaged browser startup.** Clean-profile packaged applications now load
  the required workspace definitions and runtime assets without relying on a
  developer configuration or debugger.
- **Packaged smoke isolation.** Release verification uses its own temporary
  profile and environment, preventing local settings from masking packaging
  defects.

## Tests / Verification

- The exact application head passed the macOS arm64 and Windows x64 Desktop
  qualification lanes.
- macOS passed the Desktop regression suite, real Electron browser end-to-end
  coverage, a 20-run same-runner browser comparison, clean-profile packaged
  verification, package creation, and artifact upload.
- Windows passed Desktop contracts, workspace dependency dereferencing,
  installer creation, and artifact upload.
- The browser stress run completed 1,000 warm tab switches and 100
  create/close cycles without a tab crash while retaining form and scroll
  state.
- All 11 enforced browser comparison gates passed. Blank-tab creation measured
  12.9 ms p95, warm switching 7.2 ms p95, bridge dispatch 0.7 ms p95, and
  twenty-tab incremental memory was 0.76 times the same-runner comparison
  baseline.
- A 25,000-file fixture rendered no more than 46 file rows in a 720-pixel
  viewport while retaining directory expansion across panel changes.
