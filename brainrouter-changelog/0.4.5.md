# 0.4.5 — Release hygiene, competitive catch-up, and CLI polish

0.4.4 made the memory pipeline precise; 0.4.5 closes the gap between that product
surface and its docs/distribution, picks off the highest-value competitive gaps,
and lands a deep round of CLI polish + resilience. Theme: *finish what 0.4.4
started, and make the CLI a pleasure to drive.*

Every item shipped as its own branch → PR → green CI → `--no-ff` merge into
`release/0.4.5` (PRs #193–#219). Full suite green: **508 brain unit + 150
integration + 1049 CLI**.

## Shipped

### Release hygiene

- **READMEs synced to the 0.4.x surface (HYG-1)** — both READMEs bumped, the CLI
  README gained a "What you get" 0.4.x overview + the `cli.*` config correction,
  and the brain README documents the new MCP tools.
- **Dependency pins + policy trust-model doc (HYG-3/HYG-4)** — cross-package pins
  bumped to the matching minor; a new `brainrouter-docs/policy.md` documents the
  knobs + tool→action map + profile × capability table, linked from the docs
  index and `/policy` output.
- **Published benchmark numbers (BENCH-PUB)** — a root `BENCHMARKS.md`
  consolidating recall / code-recall / scale / load / real-embeddings / e2e with
  provenance + regenerate commands, plus a fresh code-recall run (100% symbol
  isolation).

### Competitive catch-up

- **Automatic code-index freshness (CLI-REINDEX)** — a `cli.autoReindex` gate
  calls `memory_reindex_source` from reads (fire-and-forget) and write/edit/
  apply_patch (awaited, with a refresh notice), stat-gated + offline-safe, so the
  code index never silently rots between turns.
- **Expanded headless event taxonomy (HEADLESS-EVENTS)** — the JSONL stream gains
  `memory` / `offload` / `cost_update` / `approval` / `code_index` events (schema
  v1→v2, additive) via new optional RunTurnCallbacks.
- **Repo-scale code retrieval metrics (CODE-SCALE)** — a pure rank-metrics module
  (recall@k / precision@k / MRR / nDCG + token-efficiency) over a deterministic
  labelled fixture + `runCodeScaleBenchmark()`; committed numbers (recall@10
  100%, token-efficiency 19.4%) in BENCHMARKS §2b.
- **Browser verification artifacts (VERIFY-BROWSER)** — `/verify browser [url]`
  runs a configurable `cli.browserSmoke` command (no bundled browser) and
  collects screenshot/video/log artifacts under `.brainrouter/browser-smoke/`.
- **Memory-tree lifecycle docs + vault labels (TREE-VAULT)** — documented the
  source→topic→global lifecycle in memory-engine.md + a `generated:
  brainrouter-vault` frontmatter label.

### Memory depth

- **Lesson conflict detection + supersede + staleness (LESSON-HYGIENE)** — a new
  pure `lessonHygiene` module (deterministic conflict-key derivation, conflict
  detection, staleness predicate); `memory_record_lesson` gains a `supersedes`
  param that invalidates a prior lesson in the same call (existence-checked);
  `findLessonConflicts` surfaces same-subject lessons for review; and a
  conservative `sweepStaleLessons` (read-only by default; `apply` archives) prunes
  old, never-reinforced lessons. Completes the MEM-32 follow-up.
- **Rejected/duplicate blackboard review + restore (BLACKBOARD-REVIEW-UX)** — a
  candidate dropped (rejected) or deduped (duplicate) can now be **restored** to
  `pending` for re-review (`restoreBlackboardItem` + a `restore` action on
  `memory_blackboard_review`), surfaced through a new CLI `/blackboard`
  (review | list | restore | commit | reject | reconcile).
- **L0–L3 memory model docs (MEM-LEVELS)** — added the L0–L3 retention hierarchy
  + top-down recall explanation to memory-engine.md.

### Security

- **Consistent per-user API scoping (RBAC-ENFORCE)** — the per-user scope check
  (copy-pasted across four routes, returning 400/403/500 inconsistently for the
  *same* cross-user denial) is consolidated into one pure, tested
  `api/middleware/scope.ts` (`scopedUserId` + a `ScopeError` that always maps to
  **403**). Resource-by-id reads keep their ownership-404 guard; admin routes stay
  admin-gated. Documented in `policy.md`. (Audit confirmed no data leak — the gap
  was status consistency.)

### CLI resilience

- **Transient LLM retry (connectivity + HTTP 5xx/gateway/429)** — a failed model
  call is now retried (3 attempts, 0.6s/1.8s backoff) for transient connectivity
  errors AND retryable server statuses — HTTP 5xx, gateway timeouts (`504 Gateway
  Time-out`), and rate limits — instead of dying. Background workers and child
  agents (which run silent) no longer die on a network blip or a load-balancer
  hiccup. A false-positive guard keeps a bare `500` in a message from masquerading
  as a status.
- **Command registry drift guard (CMD-REGISTRY)** — a guard test fails on
  duplicate slash commands, duplicate `/help` rows, or any `/help`↔completion
  drift; fixed the existing drift.
- **Richer prefix-drift labels (PREFIX-DRIFT)** — a `prefixDrift` snapshot+diff
  surfaces tool/anchor deltas + a human label on the immutable prompt prefix.

### TUI & ergonomics

- **Width-aware table + reasoning rendering (TUI-TABLES / TUI-THINKING)** —
  model responses with GFM tables now render as proper width-fitted boxes (a
  water-fill column allocator + ANSI-aware wrapping) instead of the broken
  marked-terminal grid; reasoning panels get a dim-magenta gutter.
- **Footer: effort glyphs + offload + full session IDs (FOOTER-TELEMETRY)** — the
  footer effort indicator gained `xhigh`/`max`, a new opt-in `offload` segment
  (`child:<k> saved:~<k>`) backed by a live child-token + offload counter, and
  session IDs are shown in full (no truncation) everywhere.
- **Live background-tasks panel (BG-TASKS-PANEL)** — a panel above the composer
  lists running workflows / workers / child agents, auto-hiding when idle and
  refreshed on a ticker (and surfaced by `/bg` etc. without needing a chat turn).
- **Background-task management (CLI-BG-DETACH)** — `/fg <id>` brings a worker or
  child agent to the foreground (status + recent transcript); `/ps` now lists
  loop + workflows + workers + child agents; `/stop <id>` stops a specific one.
- **`/agents create` validation + dry-run (AGENTS-WIZARD)** — tool-scope
  *existence* validation (unknown local tool = error, unknown MCP tool = warning),
  an `ownership` glob (also used as the spawn-time default for write/shell
  children), a `--dry-run` preview, and `--mcp`/`--ownership` flags.
- **Task-graph offload view (OFFLOAD-GRAPH)** — `/context offloads graph` renders
  a Mermaid view of the offload task graph.
- **Composer history, flag suggestions, tab-to-end cursor (INPUT-ERGO)** — `↑`/`↓`
  recall previous inputs (shell-style, with draft preservation); typing
  `/cmd --<flag>` opens a flag-suggestion palette (Tab completes); and Tab /
  history / `@`-completion now move the cursor to the end of the line.
