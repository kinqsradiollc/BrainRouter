# BrainRouter 0.4.14 — Memory Recall-Quality Results

Benchmark-driven recall overhaul. Four pipeline fixes (MEM-JUDGE2, MEM-BLEND,
MEM-RERANK2, MEM-ROUTE) measured on three long-term-memory benchmarks. Full
per-split tables: [`memory-comparison.md`](memory-comparison.md).

## Setup

- **Benchmarks:** MemBench (factual `*-fm` + reflective `*-rm`, participation & observation), LongMemEval-S (session-level), LoCoMo (turn-level).
- **Slice:** `--max-records 3000 --max-queries 30`, seed `1337`; the **same** bounded slice for every system, gold records always included.
- **Stack:** live BrainRouter MCP server, local `gemma-4-e2b` (LLM + judge), local vLLM `BAAI/bge-reranker-v2-m3` (reranker), `nomic-embed-text-v1.5` (embeddings).
- **"Before"** = the 0.4.14 retriever after the granularity round (MEM-CHUNK/RERANK/JUDGE/VEC) but before this recall-quality round. **"After"** = MEM-JUDGE2 + MEM-BLEND + MEM-RERANK2 + MEM-ROUTE.

## `judge` config — recall collapse fixed (MEM-JUDGE2)

The LLM judge used to *filter* to its approved subset, collapsing recall (R@5=R@10=R@20).
It now *reorders* (approved-first) and never drops below the retriever, so `full ≥ reranker` holds.

| Split | judge R@10 Before | After |
|---|--:|--:|
| longmemeval:s | 0.50 | **0.87** |
| os-rm | 0.36 | **0.49** |
| locomo | 0.45 | 0.48 |
| ps-fm | 0.83 | 0.83 |

## What each fix does

| Fix | Change | Knob (default) |
|---|---|---|
| **MEM-JUDGE2** | judge reorders (approved-first), never drops below the retriever; reads more of each candidate | `BRAINROUTER_RELEVANCE_JUDGE_MODE` (`reorder`), `…_DOC_CHARS` (1200) |
| **MEM-BLEND** | reciprocal-rank blend of cross-encoder vs retriever (RRF + half-life recency) | `BRAINROUTER_RECALL_RERANK_BLEND_ALPHA` (1.0) |
| **MEM-RERANK2** | char-budget the cross-encoder input — long docs send fewer candidates, short docs the whole pool | `BRAINROUTER_RECALL_RERANK_CHAR_BUDGET` (30000) |
| **MEM-ROUTE** | reflective/analytical queries skip the cross-encoder (it demotes their low-overlap gold) → retriever+judge path | `BRAINROUTER_RECALL_QUERY_ROUTING` (`on`) |

## Caveats (read these with the numbers)

- **Recency baseline.** A trivial `Capped dump (recency 200)` still leads on the temporal splits (longmemeval R-any@5 0.93 vs full 0.87; os-fm R-any@5 0.80 vs 0.70). The benchmark importer stores **no per-record timestamps**, so BrainRouter's half-life recency — and the MEM-BLEND recency path — are *inert on this data*. The pipeline has the mechanism; measuring it needs importer timestamp support (follow-up). This is a benchmark-data artifact, not a pipeline gap.
- **Reflective splits are hard for everyone.** On `*-rm`, *every* system (including the full-context dump) scores low because reflective questions share little surface signal with their gold evidence, and single-gold recall@k under-counts answers that synthesize many records. Read these as diagnostic, not a ranking.
- **Precision/recall tradeoff.** The recall-safe judge default (`reorder`) lowers top-5 precision (e.g. `full` ps-fm P@5 0.42→0.19). Set `BRAINROUTER_RELEVANCE_JUDGE_MODE=filter` for the precision-max behavior (drops rejects, floored so it can't collapse to 0).
- **Latency is local-model-bound.** `reranker`/`judge`/`full` p50 is dominated by the local LLM + vLLM reranker; a hosted reranker (e.g. Cohere) is sub-second regardless of pool size.
- **Vector baseline** in the tables is a deliberately weak 64-d hash strawman, not BrainRouter's real embeddings.
