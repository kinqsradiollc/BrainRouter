Why did the reranker time out on Windows, and how was it fixed?

Claude · claude-opus-4-8

The timeout came from two places. The recall pipeline loaded the reranker on the same path as chat-only models, so under CPU pressure it kept the request open until the wall clock ran out. The fix adds a kind-aware probe that recognises embedding and reranker models and keeps them out of the chat path entirely.

A second guard sheds parallel load and applies a CPU timeout, so a slow local model degrades gracefully instead of hanging the whole recall.
