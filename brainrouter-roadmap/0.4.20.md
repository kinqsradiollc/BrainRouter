# 0.4.20 — Stacked pull requests, done properly

> Status: **PROPOSED — planning only, awaiting owner approval.** No implementation begins until
> [ADR-028](../brainrouter-docs/decisions/ADR-028-stacked-pull-requests-done-properly.md) is
> approved.

## The question this release answers

> We shipped stacked-PR support in 0.4.19 built on a guess about the feature's shape. What does it
> take to make it actually work — and how does a human know their message reached the agent at all?

## Why now

0.4.19's D13 was written the day GitHub's preview was announced, from a changelog and an overview
page, before the CLI reference existed in our research. The model and the review integration are
sound. The part that touches GitHub is wrong in one specific and serious way: **`stack.addlayer`
opens an ordinary pull request and reports that it created a stack layer.**

## Owner decisions recorded

| Question | Answer |
|---|---|
| Agent may run `gh stack sync`? | **Yes, on explicit instruction** — never on its own inference |
| Auto-propose stacks? | **Yes**, gated to `shouldStack:true` and once per change |
| Merge queue | **Wait for GitHub's native queue** — no third-party integration |

## Explicitly out of scope

- **A Trunk-specific merge-queue integration.** Waiting for GitHub's first-party support.
- **Reimplementing cascading rebase.** GitHub maintains it; ours would be a worse copy.
- **Cross-fork stacks.** Not supported by the platform.
- **Auto-merging a stack without confirmation**, however green the checks.
- **A local stack database.** `gh stack` owns local tracking; a second store would drift.
- **A "read" receipt that turns green on context inclusion.** Attention is not instrumentable; a
  receipt we cannot substantiate is worse than none.

## Non-negotiables

- `stack.addlayer` is removed before it is replaced. An action that reports success for work it did
  not do gets no deprecation window.
- History rewriting of branches under review is never agent-initiated without explicit instruction,
  and every run previews the layers it will rewrite.
- Auto-propose fires once per change and never for an indivisible one. A proposal that fires often
  is one that gets dismissed reflexively, and then it is worth nothing when it matters.
- A stack merge confirmation names **every** pull request that will land, not only the one asked for.
- Capability is detected, not assumed; where the extension is absent, stack actions are hidden
  rather than offered-and-failing.
- A message never shows "read". It shows `delivered` — what we can prove — and `acknowledged` only
  on evidence the agent consumed it. A dropped steer is always loud.
