# BrainRouter 0.4.18 Roadmap — Native Desktop Visual System

**Status:** Implementation and qualification complete; publication paused ·
**Target:** `release/0.4.18` · **Decision:** [ADR-026](../brainrouter-docs/decisions/ADR-026-desktop-native-visual-system.md)

## Release outcome

0.4.18 is a focused Desktop quality release. It will give the workbench a
platform-adaptive semantic visual system, genuine operating-system window
behavior, system appearance modes, clearer style ownership, and measurable
Editor/Files/panel responsiveness without changing agent authority, browser
isolation, terminal PTY behavior, or orchestration.

The release is intentionally split into small, reversible feature PRs.
ADR-026 was approved on 2026-07-30.

## Qualification record

Release head `f900181864403f9cf0672f0dc8dcd5ce92e38af7` passed
[Desktop qualification run 30547658722](https://github.com/kinqsradiollc/BrainRouter/actions/runs/30547658722)
on macOS arm64 and Windows x64. The macOS lane passed the Desktop regression
suite, native browser E2E, enforced 20-run Chrome comparison, clean-profile
packaged verification, and artifact upload. The Windows lane passed Desktop
contracts, dependency dereference, installer creation, and artifact upload.

The enforced browser comparison passed all 11 release gates with no failure:
blank-tab creation p95 was 12.9 ms, warm tab switching p95 was 7.2 ms, bridge
dispatch p95 was 0.7 ms, and twenty-tab incremental RSS was 0.76 times Chrome
on the same runner. The stress pass completed 1,000 switches and 100
create/close cycles without a tab crash while retaining form and scroll state.

0.4.18 remains deliberately unpublished. The qualification run was triggered
from the release branch, so tag-only release attachment steps were skipped.
There is no 0.4.18 tag, package publication, release attachment, or merge to
`main`.

## Release constraints

- Keep the preload-only Desktop capability boundary.
- Keep real platform window controls; do not imitate another operating system.
- Keep inactive right-panel views mounted so navigation preserves state.
- Keep Monaco, browser content, and terminal processes under their current
  owners.
- Do not mix runtime behavior or package restructuring into styling PRs.
- Require live macOS review and a passing Windows build/package lane before
  removing the compatibility setting.
- Keep 0.4.17 as the latest published version until the owner explicitly
  authorizes 0.4.18 publication; passing qualification does not publish it.
