# 0.4.19 — Compounding debt, graph execution, and workbench modernization

> Status: **PROPOSED — awaiting owner approval.** No implementation begins until
> [ADR-027](../brainrouter-docs/decisions/ADR-027-compounding-debt-graph-execution-and-workbench-modernization.md)
> is approved.

## The question this release answers

> How do we stop knowledge, technical, and **cognitive** debt from compounding — for the system
> *and* for the human — while making the workbench fast, coherent, and fully agent-operable?

## Why now

0.4.18 shipped a native-feeling desktop and fixed the workflow-skill preflight. What it did not
address is that the agent cannot read a PDF the user just attached, re-fetches the same web page
every session, cannot work in a worktree without losing the session, and grows a database nobody
prunes. Each of those is an instance of a debt, not an isolated bug.

## Explicitly out of scope

- **Sharding.** Not justified at current scale; partitioning by tenant captures most of the
  benefit and keeps the same future shard key. See ADR-027 §D11.
- **An external durable-execution engine.** We are below the crossover criteria.
- **CRDTs for session/plan/task state.** Convergence is not correctness and authorization has no
  home in a merge.
- **A "what you have not reviewed" notification feed** and per-action approval dialogs as the
  primary control surface — both are contradicted by the oversight evidence in ADR-027 §1.

## Non-negotiables

- 0.4.18 remains the latest published version until the owner explicitly authorizes 0.4.19.
- No implementation before ADR-027 is approved.
- Release PRs merge with a merge commit, never a squash.
