# 0.4.19 — Compounding debt, graph execution, and workbench modernization

> Status: **PROPOSED — awaiting owner approval.** No implementation begins until
> [ADR-027](../brainrouter-docs/decisions/ADR-027-compounding-debt-graph-execution-and-workbench-modernization.md)
> is approved.

## The question this release answers

> How do we stop knowledge, technical, and **cognitive** debt from compounding — for the system
> *and* for the human — while making the workbench fast, coherent, and fully agent-operable?

## Why now

0.4.18 shipped a native-feeling desktop and fixed the workflow-skill preflight. What it did not
address is that the agent cannot read a PDF the user just attached, re-fetches the same web page
every session, cannot work in a worktree without losing the session, and grows a database nobody
prunes. Each of those is an instance of a debt, not an isolated bug.

## What is blocked, and on what

Four of thirty-nine rows are outstanding, and none of them is a coding task.

**Three visual rows — P2-5, P4-1, P4-5.** UI work requires screenshot approval before
commit. The admin model editor is auth-gated (verified: `/providers` redirects to the
landing page without credentials), so the form cannot be rendered for review from an
unauthenticated session.

**Two decisions in [ADR-027 §5](../brainrouter-docs/decisions/ADR-027-compounding-debt-graph-execution-and-workbench-modernization.md).**

1. **Does the graph engine replace `runTurn` in 0.4.19?** The engine, its typed state,
   and compensation ordering all exist (#1283, #1284) and touch nothing. Whether it
   *supplants* the turn loop every other phase runs on is the open question — a wrong
   assumption there costs the release rather than a delay.
2. **Which design language?** P4-1 is a full visual system, and a guessed answer is
   work that gets redone rather than work that lands early.

**One authorisation.** The attachment storage migration has a planner, an independent
verifier, and a dry-run-by-default executor (#1274). Pointing it at real files is an
operational decision, not a code change.

Answered so far, and both unblocked the work that followed them: the local review gate is
**advisory by default with opt-in blocking**, and append-forever data keeps **90 days of
detail before compaction**.

## Explicitly out of scope

- **Sharding.** Not justified at current scale; partitioning by tenant captures most of the
  benefit and keeps the same future shard key. See ADR-027 §D11.
- **An external durable-execution engine.** We are below the crossover criteria.
- **CRDTs for session/plan/task state.** Convergence is not correctness and authorization has no
  home in a merge.
- **A "what you have not reviewed" notification feed** and per-action approval dialogs as the
  primary control surface — both are contradicted by the oversight evidence in ADR-027 §1.

## Non-negotiables
