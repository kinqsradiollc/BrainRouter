# 0.4.17 Roadmap — Runtime Body and Product Completion

**Status.** In progress.
Full release notes: [`../brainrouter-changelog/0.4.17.md`](../brainrouter-changelog/0.4.17.md).

**Theme.** Complete the runtime, shared workspace, project onboarding, and
project-knowledge paths without broadening default authority. Each independently
reviewed slice must pass CI and security review before entering the release branch.

| Thread | Goal | Status |

## Why This Release Exists

- BrainRouter already spans CLI, desktop, dashboard, and the brain, but project
  intent and setup must remain consistent across those surfaces and restarts.
- Users should describe a project in ordinary language, review the proposed
  agents/capabilities/skills/tools, and retain authority over every write.
- Research and study workspaces need source-grounded project knowledge without
  weakening organization, Project, or cognitive-memory boundaries.
- Expanded runtime and automation authority must stay explicit, scoped, and
  observable rather than becoming a new default.

## Acceptance

- A fresh installation commits global setup before offering project setup; abort,
  Skip, and failed writes preserve the previous usable state.
- Opening a later project runs only project setup, and edit mode preserves safe
  unknown fields.
- A failed BrainRouter switch cannot replace the current live/durable selection
  or poison the next reconnect.
- Frontend signals activate engineering support without selecting another agent.
- Project knowledge rejects inaccessible organization/Project identifiers with no
  cross-tenant disclosure and always returns source provenance.
- No manifest preserves legacy prompt, tool, skill, briefing, and memory behavior.

## Ship Gate

- `npm run build`
- `npm run verify` with PostgreSQL available
- Required GitHub CI, dependency audit, mobile, and BrainRouter security review
- Live CLI first-run, later-workspace, edit, assisted/fallback, and failure walkthrough
- Live desktop onboarding/settings/accessibility and project-switch walkthrough
- Live backend/dashboard/desktop knowledge ingest, status, search, citation, and RBAC walkthrough
- Reconciled changelog, versions, package contents, and release tag

## Out of Scope

- A separate frontend persona or harness role.
- Authorization derived from local paths, workspace tags, or client-supplied
  organization/user identity.
- Automatic project-file mutation from model output without visible review and
  explicit confirmation.
- A second cognitive-memory system for source documents.
