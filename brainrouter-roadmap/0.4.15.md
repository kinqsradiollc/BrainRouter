# 0.4.15 Roadmap — The Agent Behind the Glass

**Status.** Planned — branch `release/0.4.15`.
Full release notes (when shipped): [`../brainrouter-changelog/0.4.15.md`](../brainrouter-changelog/0.4.15.md).

**Theme.** 0.4.14 gave the CLI its grid TUI shell. 0.4.15 upgrades **the process
behind it** — the agent loop, prompt architecture, context engine, and session
lifecycle — to match the behavior of the strongest reference coding agents, while
keeping the 0.4.14 UI. Boundary: no new memory-engine work (0.4.14 closed that),
no dashboard work, no federation expansion. Every thread below is CLI runtime.

## Release Threads

| Thread | Goal | Status |
|---|---|---|
| A. Chat ergonomics | The terminal *feels* native: line-level smooth scrolling, mouse wheel + scroll-speed, collapsible tool results, transcript search, Esc-to-interrupt, `/copy`·`/export`, Ctrl+R history search. Keeps the grid/sidebar chrome. | Planned |
| B. Agent-loop behavior | The model *acts* like a top-tier agent: layered system-prompt architecture, final-message deliverable contract, parallel-batching discipline, read-before-edit + unique-match edit semantics, verification-before-done gate, subagent structured-output contracts. | Planned |
| C. Context engine | Token discipline: byte-stable cached prefix (volatile state moves to turn-end reminders), a tagged system-reminder channel, normalized tool-result truncation with "read more" affordances, structured compaction summaries (task state / files / decisions / next steps). | Planned |
| D. Session lifecycle | `--continue` / `--resume` + `/resume` picker, `/rewind` turn restore (with optional file-snapshot restore), `/branch` forks, `/rename` · `/recap`. | Planned |
| E. Guardrails & permissions | Plan permission mode (read-only until an approved plan, 4th Shift+Tab mode), declarative `cli.permissions` allow/ask/deny rules + "always allow" persistence, network domain rules. | Planned |
| F. Extensibility | Markdown slash commands (`.brainrouter/commands/*.md` + `$ARGUMENTS`), hook-event breadth (pre/post tool-use with decision contracts, prompt-submit, stop, pre-compact), background shell tasks, `!` / `#` composer prefixes. | Planned |
| G. Behavior measurement | An **agent-behavior benchmark** in `brainrouter-benchmark`: scripted headless tasks scored on batching rate, premature-question rate, verification rate, deliverable completeness, edit-failure rate, tokens-per-task — the gate every thread above must move. | Planned |

## Why This Release Exists

- The 0.4.14 TUI made the *surface* competitive; transcripts show the *behavior*
  still trails reference agents: serialized tool calls that could batch, answers
  that end in "let me know if…" instead of a deliverable, edits that clobber
  because nothing enforces read-before-edit, and context that breaks the provider
  prompt cache every turn.
- Behavior is currently tuned by prompt-tweaking and judged by feel. Thread G
  makes it measurable, so "matches the reference agents" becomes a number that
  can gate PRs — the same playbook that fixed recall in 0.4.14.
- Out of scope (deferred to 0.4.16+): vim/emacs composer modes, image paste,
  `/doctor`, `/usage` category breakdown, model fallback chains, output styles,
  plugin marketplaces.

## Implementation Summary

| # | Item | Result / target |
|---:|---|---|
| A1 | Line-level virtual scrolling (visual-line window over the entry packer) | Scrolling moves by line, not entry; no jumps on tall messages |
| A2 | Mouse-wheel scroll (opt-in SGR mouse reporting) + `cli.scrollSpeed` | Two-finger scroll works inside the managed frame |
| A3 | Collapsible tool results / turn groups + verbose-transcript toggle | Long sessions stay scannable |
| A4 | Transcript search (`/find`, n/N jump) | Find anything said this session |
| A5 | Esc interrupts a running turn (idle Esc keeps scroll mode); `/copy` · `/export`; Ctrl+R reverse history search | Interrupt parity + retrieval conveniences |
| B1 | System-prompt architecture: composable layered sections (identity → communication contract → tool discipline → safety → environment) with per-section token budgets + per-model overlays | Replaces the monolithic prompt; budget test per section |
| B2 | Final-message deliverable contract + turn-end guard | Zero turns that end on a promise instead of a result |
| B3 | Parallel-batching discipline (prompt + measurement) | Batching rate ≥ reference baseline on the G suite |
| B4 | Read-before-edit + unique-match edit semantics on file tools | Edit-failure rate cut measurably on weak models |
| B5 | Verification-before-done gate (build/test evidence for code changes) | Unverified "done" claims caught at turn end |
| B6 | Subagent output contracts: final-message-is-result + JSON-schema structured output with validate-and-retry | Parents stop re-parsing child prose |
| C1 | Byte-stable prompt prefix; volatile state → turn-end reminders | Provider cache hit-rate measurably up (`/context prefix` drift = 0) |
| C2 | Tagged system-reminder channel for ephemeral state (plan sync, completion inbox, queued notices) | One injection path, cache-safe |
| C3 | Tool-result truncation contract with offset/limit affordances | No silent loss; "read more" everywhere |
| C4 | Structured compaction summaries + post-compaction recall re-injection | Post-compaction turns keep working state |
| D1–D4 | `--resume`/`--continue` + picker · `/rewind` (+file restore) · `/branch` · `/rename`/`/recap` | Session lifecycle parity |
| E1–E3 | Plan mode · `cli.permissions` rules + always-allow · network domain rules | Safety parity without prompt fatigue |
| F1–F4 | MD slash commands · hook decision contracts · background shell · `!`/`#` prefixes | User extensibility parity |
| G1 | Agent-behavior benchmark suite + baseline report | Every B/C item lands with a before/after number |
| G2 | Transcript-diff tooling (same task, reference agent vs ours, normalized decision trace) | Gap discovery is systematic, not anecdotal |

## Sequencing

1. **G1 first** (baseline before changing behavior), in parallel with **A1–A2**
   (the active ergonomic pain).
2. **B1–B2 + C1–C2** (prompt architecture + cache discipline — the foundation
   every other behavior change sits on).
3. **D1–D2** (resume/rewind), **B3–B6**, **A3–A5**, **C3–C4**.
4. **E**, **F**, **G2**, then the 0.4.16 cut for whatever the benchmark says
   matters next.

Each item ships as its own PR into `release/0.4.15`, test-first, suite green,
with its G-suite delta in the PR description where applicable.
