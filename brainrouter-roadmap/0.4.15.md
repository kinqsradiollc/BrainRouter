# 0.4.15 Roadmap — The Agent Behind the Glass

**Status.** Planned — branch `release/0.4.15`.
Full release notes (when shipped): [`../brainrouter-changelog/0.4.15.md`](../brainrouter-changelog/0.4.15.md).

**Theme.** A **complete reverse-engineering of the strongest reference coding
agent**, rebuilt as BrainRouter — not a gap list, a full decomposition. The
reference agent is treated as twelve subsystems (prompt OS, tool contracts, turn
engine, task system, orchestration, background runtime, context OS, memory,
safety, session lifecycle, interaction layer, headless surface); each is mapped
against what BrainRouter already has and the delta becomes a thread below. The
0.4.14 grid TUI stays — this release is everything *behind* it.

**Method.** Three sources, in order of authority: (1) live behavioral observation
— run the reference agent on scripted tasks and capture its decision traces
(prompt structure, batch shapes, guard behavior, recovery patterns); (2) its
public docs/changelog corpus; (3) probing edge cases (denied tools, compaction,
interrupts). Every finding lands as a *contract* (testable rule), never copied
prose. Thread L's benchmark turns "matches the reference" into a number.

**Explicit non-goals (cannot or will not copy).** The model itself (interleaved
thinking quality is a model property — BrainRouter must work on weaker OS models,
which is why contracts become *enforced guards*, not polite prompt suggestions);
vendor cloud infra (remote-control apps, IDE extensions, plugin marketplaces);
voice. Dashboard/federation/memory-engine work stays out of this release.

## Why This Release Exists

- 0.4.14 made the surface competitive; the *system* behind the reference agent is
  what makes it feel senior: contracts (not vibes) for how it communicates, acts,
  batches, verifies, recovers, and reports. Encoding those as enforceable guards
  is exactly the trick that already works here (preambleGuard family) — 0.4.15
  generalizes it into a full behavioral spec.
- Several whole subsystems have no BrainRouter counterpart yet (task tracker,
  programmable workflows, monitor/cron/loop, structured questions, rewind,
  stream-json). After this ships, the CLI is a *complete* agent platform, not a
  chat loop with strong memory.
- Thread L exists so "fully matches the reference" is falsifiable — the same
  benchmark-gated playbook that fixed recall in 0.4.14.

## Thread M — Desktop app (DESK-0..7)

**Why it is cheap here:** the agent core is already UI-agnostic. A turn is
`Agent.runTurn(prompt, callbacks)` with 14+ streaming callbacks (assistant/
reasoning deltas, tool + child-tool lifecycle, plan, compaction, approval,
memory, status), the headless `run --format jsonl` protocol already names the
event vocabulary, and the session/worker/workflow/plan/goal state is file-backed
and read through pure modules (recap, usage, chapters, search, export, fleet).
The TUI is one presentation head; the desktop app is a second head on the same
body — no agent rewrite.

**Stack decision:** Electron + React 18 + Vite + TypeScript.
- The entire runtime is Node (MCP pool child processes, shell spawns, fs-backed
  stores) — Electron's `utilityProcess` runs it UNMODIFIED as a long-lived
  per-workspace agent host. The Rust-shell alternative (smaller binaries) would
  need a bundled Node sidecar anyway, forfeiting the reuse win and doubling the
  runtime surface; revisit only if footprint becomes a complaint.
- Renderer: React + Vite SPA (not Next — no server), reusing the dashboard's
  design language; full-height sidebar identity preserved (non-negotiable).
- Distribution: electron-builder (notarized dmg arm64+x64, signed NSIS exe) +
  electron-updater over GitHub releases. Signing certs are a user-owned
  prerequisite; CI builds unsigned artifacts until they land.

**Process architecture:**

    main process (lifecycle, windows, updater, tray)
      └─ agent host  — utilityProcess per workspace: the brainrouter-cli runtime
         (Agent, orchestration, workers, stores, MCP pool) + protocol adapter
      └─ renderer    — React, contextIsolation on, typed preload bridge only
    renderer ⇄ main ⇄ host speak ONE typed protocol (packages/agent-protocol)

**Phases — one branch + CI-gated PR each (the #350–#373 discipline):**

- [ ] **DESK-0 Agent protocol + interaction port.** New `packages/agent-protocol`:
      zod-typed events (the 14 callbacks + approval/status) and commands
      (startTurn, interrupt, approve, answerChoice, listSessions, resume, …),
      shared by desktop IPC and the CLI's jsonl mode. In the agent: generalize
      the TTY seams (`askYesNo`, `ask_user_choice`, approval prompts) behind an
      injectable `InteractionPort` — CLI implements it with readline, desktop
      with IPC dialogs. Pure + heavily tested; benefits headless CI too.
- [ ] **DESK-1 Electron shell scaffold.** `brainrouter-desktop/` workspace:
      main + preload + renderer skeleton, agent host boot with handshake,
      typed IPC bridge, Vite dev loop, mac/win CI build matrix (unsigned).
- [ ] **DESK-2 Chat core.** Streaming markdown with code highlighting, tool
      cards (collapsible previews, real diff rendering), plan checklist, live
      child-fleet rows, **Stop button** — lands the turn-abort plumbing
      (AbortSignal through the LLM call + tool loop) once in the agent, which
      retires the TUI's open Esc-interrupt item (P1.5) for both heads.
- [ ] **DESK-3 Approvals + composer.** Approval modal queue over the
      InteractionPort (tool / dangerous-command / delegation / MCP approvals),
      structured multi-choice question dialogs (closes the ask_user_choice
      parity remainder, P12.1), composer with slash palette, @-mentions,
      `!` and `#` prefixes, history + reverse search.
- [ ] **DESK-4 Surfaces.** Right sidebar (context card + live Sub-agents /
      Workers / Workflows fleet), sessions drawer (list / resume / recap),
      chapters TOC with click-to-jump, transcript search panel, usage panel,
      export — all thin React over the existing pure modules.
- [ ] **DESK-5 Workspace + settings.** Folder picker (window per workspace),
      provider/model settings UI over config.json, `cli.permissions` rules
      editor, hooks manager, theme system from the dashboard design language.
- [ ] **DESK-6 Packaging.** Icons, single-instance + deep links, notarization
      + signing pipelines, auto-update channel (alpha), release artifacts
      attached to the GitHub release.
- [ ] **DESK-7 Hardening.** Electron security checklist (contextIsolation,
      sender-frame validation, CSP, no remote content), Playwright-for-Electron
      smoke (boot → turn → approval → stop), desktop sessions feeding the
      behavior benchmark, opt-in crash reporting.

**Scope effects on the open TUI items:** P1.2 (mouse wheel) is obsolete in a
DOM renderer (free) — closed by M; P1.5 (interrupt) and P12.1/P12.2 land inside
DESK-2/3 as shared agent work; P7.1/P7.2 and P10 remain agent-side threads
unchanged. The TUI stays first-class — the desktop app ships 0.4.15 as
**alpha** artifacts beside it.

**External design review (2026-06-10) absorbed.** A product review of the
desktop direction confirmed the architecture (Electron-first; typed event
stream over the runtime — ours runs in-process via utilityProcess, strictly
better than subprocess output-scraping) and set the completeness bar: the
four-panel coding-agent layout (sessions rail · chat · review pane · terminal),
diff/changed-files review, command terminal, token usage, and later: per-hunk
accept/reject, editor pane (Monaco), memory panel, workflow timeline, SQLite
session index, OS-keychain secrets, edit-command-before-run approvals. The
first four shipped in DESK-4; the rest are DESK-5/6/7 backlog.

**MVP cut-line:** DESK-0 → DESK-2 = a usable chat with approvals and stop.
Everything after is surface area.

## Sequencing

1. **L1 baseline** (measure before changing behavior) ∥ **A1–A2** (active pain).
2. **B1 + D1–D2** (prompt architecture + cache/reminder discipline — the
   foundation everything else writes into).
3. **B2–B7 + C1–C4** (behavior + tool contracts, each gated on L deltas).
4. **E + H1–H2** (task system, resume/rewind) ∥ **F** (programmable workflows).
5. **G + I + J**, then **K**, **L2**, and the 0.4.16 cut for whatever the
   benchmark says still trails.

Each item ships as its own PR into `release/0.4.15`, test-first, suite green,
with its L-suite delta in the PR description where applicable.
