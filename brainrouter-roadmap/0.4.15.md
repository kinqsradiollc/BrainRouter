# 0.4.15 Roadmap — The Agent Behind the Glass

**Status.** Planned — branch `release/0.4.15`.
Full release notes (when shipped): [`../brainrouter-changelog/0.4.15.md`](../brainrouter-changelog/0.4.15.md).

**Theme.** A **complete reverse-engineering of the strongest reference coding
agent**, rebuilt as BrainRouter — not a gap list, a full decomposition. The
reference agent is treated as twelve subsystems (prompt OS, tool contracts, turn
engine, task system, orchestration, background runtime, context OS, memory,
safety, session lifecycle, interaction layer, headless surface); each is mapped
against what BrainRouter already has and the delta becomes a thread below. The
0.4.14 grid TUI stays — this release is everything *behind* it.

**Method.** Three sources, in order of authority: (1) live behavioral observation
— run the reference agent on scripted tasks and capture its decision traces
(prompt structure, batch shapes, guard behavior, recovery patterns); (2) its
public docs/changelog corpus; (3) probing edge cases (denied tools, compaction,
interrupts). Every finding lands as a *contract* (testable rule), never copied
prose. Thread L's benchmark turns "matches the reference" into a number.

**Explicit non-goals (cannot or will not copy).** The model itself (interleaved
thinking quality is a model property — BrainRouter must work on weaker OS models,
which is why contracts become *enforced guards*, not polite prompt suggestions);
vendor cloud infra (remote-control apps, IDE extensions, plugin marketplaces);
voice. Dashboard/federation/memory-engine work stays out of this release.

## Release Threads

| Thread | Subsystem | Goal | Status |
|---|---|---|---|
| A | Chat ergonomics | Native feel inside the grid TUI: line-level smooth scrolling, mouse wheel + `cli.scrollSpeed`, collapsible tool results, transcript search, Esc-to-interrupt, `/copy`·`/export`, Ctrl+R history search. | Planned |
| B | Prompt OS + turn engine | Layered system-prompt architecture with per-section budgets; behavior **contracts encoded as guards**: deliverable-in-final-message, parallel batching, act-don't-ask autonomy with the assessment-mode exception (user describing ≠ user requesting), denied-tool semantics (adjust, never retry verbatim), evidence-before-state-change, faithful failure reporting, verification-before-done. | Planned |
| C | Tool contracts | Per-tool discipline: read-before-edit + unique-match edits, read-before-overwrite on write, offset/limit partial reads with explicit "+N more" affordances, Bash call descriptions, background flag on shell. | Planned |
| D | Context OS | Byte-stable cached prefix (volatile state → turn-end tagged reminders), one `system-reminder` injection channel, structured compaction summaries (task state / files / decisions / next steps) + continuation contract ("summary carries the work forward — don't wrap up early"), instruction-file hierarchy + imports. | Planned |
| E | Task system | First-class task tracker (create/update/list, statuses, ids) replacing bare `update_plan`; harness nudges when tracking goes stale; tasks linked to background actors. | Planned |
| F | Programmable workflows | Script-driven orchestration on top of PhasePlan: sequential/parallel/pipeline stages as *code*, JSON-schema-validated child outputs (validate + retry), per-run token budgets, journal-based resume; live run view. | Planned |
| G | Background runtime | Background shell with output polling (`/tasks` + a wait-until tool), completion re-invocation of the main loop (extends the 0.4.14 inbox), cron-scheduled agents, self-pacing recurring loop command. | Planned |
| H | Session lifecycle | `--continue`/`--resume` + `/resume` picker, `/rewind` turn restore (+ optional file-snapshot restore), `/branch` forks, session chapters (jumpable TOC), `/rename`·`/recap`·`/export`. | Planned |
| I | Safety & permissions | Plan mode (4th Shift+Tab mode: read-only until an approved plan), declarative `cli.permissions` allow/ask/deny rules + "always allow" persistence from prompts, network domain rules, hook gates with decision JSON (pre/post tool-use). | Planned |
| J | Interaction layer | Structured multi-choice questions (options + headers + multi-select) instead of free-text clarifications; out-of-scope "spin this off" task chips; skill auto-trigger semantics (trigger/skip rules in descriptions); markdown slash commands with `$ARGUMENTS`; `!`/`#` composer prefixes. | Planned |
| K | Headless / SDK surface | `-p` print mode parity: `--output-format json|stream-json` event protocol (init / message / tool_call / tool_result / stop), stable exit codes, `--max-turns`, tool allowlist flags — the automation surface CI can trust. | Planned |
| L | Behavior measurement | The gate: agent-behavior benchmark (batching rate, premature-question rate, verification rate, deliverable completeness, edit-failure rate, tokens-per-task) + reference-transcript diffing. Baseline before B lands; every behavior PR ships its delta. | Planned |

## Why This Release Exists

- 0.4.14 made the surface competitive; the *system* behind the reference agent is
  what makes it feel senior: contracts (not vibes) for how it communicates, acts,
  batches, verifies, recovers, and reports. Encoding those as enforceable guards
  is exactly the trick that already works here (preambleGuard family) — 0.4.15
  generalizes it into a full behavioral spec.
- Several whole subsystems have no BrainRouter counterpart yet (task tracker,
  programmable workflows, monitor/cron/loop, structured questions, rewind,
  stream-json). After this ships, the CLI is a *complete* agent platform, not a
  chat loop with strong memory.
- Thread L exists so "fully matches the reference" is falsifiable — the same
  benchmark-gated playbook that fixed recall in 0.4.14.

## Sequencing

1. **L1 baseline** (measure before changing behavior) ∥ **A1–A2** (active pain).
2. **B1 + D1–D2** (prompt architecture + cache/reminder discipline — the
   foundation everything else writes into).
3. **B2–B7 + C1–C4** (behavior + tool contracts, each gated on L deltas).
4. **E + H1–H2** (task system, resume/rewind) ∥ **F** (programmable workflows).
5. **G + I + J**, then **K**, **L2**, and the 0.4.16 cut for whatever the
   benchmark says still trails.

Each item ships as its own PR into `release/0.4.15`, test-first, suite green,
with its L-suite delta in the PR description where applicable.
